# 0006. i18n: i18next, chosen for the untranslated marker

Vietnamese, English and French, with Vietnamese as the source locale and a visible marker wherever
a string falls back. `i18next` 26.4.2 with `react-i18next` 17.0.14 (both MIT) is the only candidate
that does fallback _and_ reports per-string which locale satisfied the lookup, which is exactly what
requirement F9 needs.

## Status

accepted

## The trap in the obvious answer

i18next's `missingKeyHandler` / `saveMissing` **do not fire when a key resolves through
`fallbackLng`** — the resolver walks the entire fallback chain and only reports "missing" when the
key is absent from every language. Building the untranslated badge on `missingKeyHandler` would
therefore produce a badge that never appears, and the bug would be invisible: the page would look
correct and silently claim French content that is actually Vietnamese.

The mechanism that works is `returnDetails`:

```ts
const d = t('gambit.legals-mate.intro', { returnDetails: true })
if (d.usedLng !== currentLocale) {
  /* render the untranslated marker */
}
```

`usedLng` is the locale that actually satisfied the lookup, so `usedLng === 'vi'` while the visitor
is browsing `/fr/` is an exact, per-string signal.

## Considered options

Versions and licences verified on 2026-09-16.

| Option                                     | Licence      | gzip         | Fallback + per-string detection                                                                                                                                                                                                                          |
| ------------------------------------------ | ------------ | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **i18next 26.4.2 + react-i18next 17.0.14** | MIT          | 23.4 KB      | Yes, via `returnDetails.usedLng`                                                                                                                                                                                                                         |
| @lingui 6.7.0                              | MIT          | 4.1 KB       | Only by disabling its own `fallbackLocales` and hand-rolling a `missing` callback against a separately loaded Vietnamese catalogue — two catalogues per non-Vietnamese visitor                                                                           |
| Paraglide 2.25.2                           | MIT          | compile-time | **No.** Fallback is resolved inside the compiler, so a missing French string compiles to the Vietnamese literal and the caller receives an ordinary string with no signal. Also navigates the document on locale change, which is wrong on a static host |
| react-intl 12.0.2                          | BSD-3-Clause | 15.0 KB      | Yes, via `onError` — but ICU-only syntax for no advantage here                                                                                                                                                                                           |
| typesafe-i18n 5.27.1                       | MIT          | 1.27 KB      | Makes a missing key a _compile_ error, forbidding partial translations — the opposite of an incrementally translated site                                                                                                                                |

**Why this one:** F9 is a hard requirement and Paraglide cannot satisfy it at all. Lingui's 4.1 KB
is a real saving — 19 KB of a 200KB budget — but it is bought by running two catalogues and
hand-rolling the fallback, and a hand-rolled correctness mechanism in the one place the product
promises honesty is a bad trade.

**Why not the others:** typesafe-i18n's model is incompatible with the release strategy, which
explicitly ships untranslated content rather than blocking on translation.

## Consequences

- Locale bundles lazy-load via `i18next-resources-to-backend` wrapping a dynamic `import()`; Vite
  emits one chunk per locale, so a visitor downloads one language, not three.
- **Measured on implementation (#7): a non-Vietnamese visitor downloads _two_ catalogues, not
  one.** i18next loads the entire fallback resolve hierarchy, so `/fr/` fetches `fr` _and_ `vi`.
  This is not avoidable and not a defect — rendering Vietnamese fallback text requires having the
  Vietnamese text, which is what requirement F9 asks for — but it means the "two catalogues per
  non-Vietnamese visitor" counted against Lingui in the table above is a property i18next shares.
  The distinguishing reason for this choice is therefore the hand-rolled `missing` callback alone,
  not the catalogue count. The catalogues are ~0.5 KB gzipped each, so the cost is negligible
  either way; what would change is the honesty of the comparison, so it is recorded here.
- The locale lives in the URL's first path segment (ADR-0009), not in i18next. A `/:locale` route
  parameter drives `changeLanguage`.
- `CustomTypeOptions['resources']` is augmented so keys are autocompleted and typos are compile
  errors — the type safety typesafe-i18n offers, without its release-blocking semantics.
- **Chess notation is never localised.** SAN is SAN in all three languages; a Vietnamese learner
  reads `Nf3` exactly as every other chess resource shows it (`design-system.md`, §7).
- 23.4 KB is ~12% of the initial-JS budget. Tracked, and the reason Lingui stays recorded as a
  fallback rather than forgotten.
- **Measured on implementation (#7): the real cost is 16.69 KB gzipped, not 23.4 KB.** Initial JS
  went from 101.44 KB to 118.13 KB as reported by Vite's own build output, for the libraries plus
  this ticket's own components. The worst-case visitor — French, so two catalogues — downloads
  119.28 KB of the 200 KB budget. The estimate above was conservative by about 6.7 KB; the
  decision stands more comfortably than it was recorded as standing, and Lingui's saving over the
  measured figure is ~12.6 KB rather than ~19 KB.

## What would change this

The bundle budget coming under real pressure, at which point Lingui's 19 KB saving becomes worth the
hand-rolled fallback — but only with a test that proves the untranslated marker actually appears.
